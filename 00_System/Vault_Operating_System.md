# Vault Operating System

Status: living-system  
Stand: 2026-05-17

## Zweck

Diese Seite ist das Cockpit des Vaults. Sie hält zusammen, was gleichzeitig gelten muss:

- Karpathy-Style Denkraum.
- Belegarchiv.
- Topic Lifecycle.
- Claim-Review.
- Notion-Sync.
- Automation.

## Grundsatz

Der Vault ist keine reine Evidenzmaschine. Er ist ein Denk- und Wissenssystem:

```text
capture -> scope -> link -> compress -> question -> compile -> reuse
```

Evidenz-Gates schützen nur die Verwendung von Aussagen. Sie blockieren nicht das Sammeln, Fragen, Verlinken und Denken.

## Zonen

### Denkzone

Status:

- `inbox`
- `scoping`
- `signal`
- `hypothesis`
- `open question`

Erlaubt:

- sammeln.
- taggen.
- Fragen definieren.
- Domain mappen.
- Muster erkennen.
- Begriffe testen.
- alte Notizen reaktivieren.

Nicht erlaubt:

- factual claims.
- öffentliche Synthesen.
- Theorieintegration als Evidenz.

### Prüfzone

Status:

- `evidence-linked`
- `contested`

Erlaubt:

- Quellen rückverfolgen.
- Kontext validieren.
- Gegenbelege sammeln.
- interne Synthesen vorbereiten.

### Aussagezone

Status:

- `claim-ready`

Erlaubt:

- Notion-Zusammenfassung.
- Exposé- oder Antragstext.
- Lehre.
- öffentliche Synthese.

Voraussetzung:

- Mehrquellenvalidierung.
- Human Review.
- Widerspruchsprüfung.
- klare Geltungsgrenze.

## Aktuelle Risiken

1. `Digital Rooms` könnte zu breit bleiben.
2. `Public / Built Room` braucht ein konkretes Artefakt.
3. Theorie-Pyramide könnte noch zu groß sein.
4. Denkspuren dürfen nicht versehentlich zu Claims werden.
5. Notion darf nicht aktueller werden als der Vault.
